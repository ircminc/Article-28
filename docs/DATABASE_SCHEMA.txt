================================================================================
APG 835/837 RATE ANALYZER — DATABASE SCHEMA REFERENCE
================================================================================

Source of truth: backend/db/database.py (SQLAlchemy 2.0 ORM models)
Current engine:  SQLite (file: backend/data/apg_analyzer.db, async via aiosqlite)
Target ports:    SQL Server (any modern version), PostgreSQL (asyncpg)

Type-mapping conventions for ports:
  Python type         | SQLite        | SQL Server         | PostgreSQL
  -----------------   | ------------- | ------------------ | ----------------
  Mapped[int] (PK)    | INTEGER       | INT IDENTITY(1,1)  | SERIAL
  Mapped[str](N)      | VARCHAR(N)    | NVARCHAR(N)        | VARCHAR(N)
  Mapped[Decimal]     | NUMERIC(p,s)  | DECIMAL(p,s)       | NUMERIC(p,s)
  Mapped[date]        | DATE          | DATE               | DATE
  Mapped[datetime]    | DATETIME      | DATETIME2          | TIMESTAMP
  Mapped[bool]        | INTEGER 0/1   | BIT                | BOOLEAN
  Mapped[dict] (JSON) | TEXT (JSON)   | NVARCHAR(MAX)      | JSONB
                                       (or JSON column in
                                        SQL Server 2016+)

Decimal precisions are LOAD-BEARING. Money fields use 14-digit precision with
2 decimal places (NUMERIC(14,2)) — never widen to float when porting. APG
weights use NUMERIC(12,6) to preserve six decimal places of relative weight.

All identifier columns named `id` are surrogate primary keys with auto-
increment. Foreign keys named `<entity>_id_fk` reference the parent's `id`
column with the cascade behavior noted on each table.

================================================================================
1. hcpcs_to_eapg
================================================================================
PURPOSE  Maps HCPCS/CPT procedure codes to their EAPG assignments under
         eMedNY's Solventum v3.18 taxonomy. Date-bounded by quarter.
SOURCE   eMedNY APG Crosswalk workbook (APGcrosswalkMMDDYYYY.xlsx),
         "HCPCS to EAPGs" sheet. Loaded by backend/db/init_crosswalk.py.
LOAD     Replace-all on each upload.

COLUMN                       | TYPE                | NOT NULL | NOTES
-----------------------------|---------------------|----------|---------------
id                           | INT (auto)          | yes      | PK
hcpcs                        | VARCHAR(12)         | yes      | indexed
description                  | VARCHAR(512)        | no       |
eapg                         | INT                 | yes      | indexed
eapg_desc                    | VARCHAR(512)        | no       |
eapg_type                    | VARCHAR(64)         | no       | indexed; v3.18 string
eapg_category                | VARCHAR(256)        | no       |
eapg_service_line            | VARCHAR(32)         | no       |
quarter_effective_date       | DATE                | no       | indexed
quarter_end_date             | DATE                | no       | inclusive end
mid_quarter_effective_date   | DATE                | no       |
mid_quarter_end_date         | DATE                | no       |

INDEXES
  ix_hcpcs_eapg_code_date  (hcpcs, quarter_effective_date)

LOOKUP RULE (engine):
  WHERE hcpcs = :code
    AND (quarter_effective_date IS NULL OR quarter_effective_date <= :dos)
    AND (quarter_end_date       IS NULL OR quarter_end_date       >= :dos)
  ORDER BY quarter_effective_date DESC NULLS LAST
  LIMIT 1

2. icd10_to_eapg
================================================================================
PURPOSE  Maps ICD-10-CM diagnosis codes to their EAPG assignments. Used both
         for the visit-purpose adjustment on Incidental E/M codes and for
         pure-fallback EAPG resolution when HCPCS doesn't map.
SOURCE   eMedNY APG Crosswalk, "ICD-10 DX to EAPGs" sheet.
NORMALIZATION
  dx_code is stored UPPER + DOTS-STRIPPED (e.g. 'I10.0' -> 'I100',
  'i48.91' -> 'I4891'). Loader applies normalize_dx_code() before insert.
  Engine applies the same normalizer on lookup so any user input format
  resolves correctly.

COLUMN              | TYPE          | NOT NULL | NOTES
--------------------|---------------|----------|---------------------------
id                  | INT (auto)    | yes      | PK
dx_code             | VARCHAR(12)   | yes      | indexed; normalized form
description         | VARCHAR(512)  | no       |
gender              | VARCHAR(4)    | no       | '0' (any) | 'M' | 'F'
eapg                | INT           | yes      | indexed
eapg_desc           | VARCHAR(512)  | no       |
eapg_type           | VARCHAR(64)   | no       | indexed
eapg_category       | VARCHAR(256)  | no       |
eapg_service_line   | VARCHAR(32)   | no       |
effective_date      | DATE          | no       | indexed
end_date            | DATE          | no       | inclusive

INDEXES
  ix_icd10_eapg_code_date  (dx_code, effective_date)


================================================================================
3. apg_weights
================================================================================
PURPOSE  Relative weight per EAPG by effective date. Used by the APG engine
         to compute payment = weight × base_rate × adjustments.
SOURCE   NYS DOH history_and_fee_schedule.xls, "Final APG Based Weights" sheet.
SHAPE    Long form. One row per (apg, effective_date). At query time the
         engine selects the most-recent effective_date <= DOS.

         A "final rate" row uses sentinel effective_date = 9999-12-31 with
         is_final_rate = true and year_rate set to the year it covers.
         Engine prefers final_rate when year_rate >= year(dos).

COLUMN          | TYPE          | NOT NULL | NOTES
----------------|---------------|----------|----------------------------
id              | INT (auto)    | yes      | PK
apg             | INT           | yes      | indexed
apg_description | VARCHAR(512)  | no       |
effective_date  | DATE          | yes      | indexed; sentinel 9999-12-31 for final
weight          | DECIMAL(12,6) | yes      | relative weight, 6dp
is_final_rate   | BIT/BOOL      | yes      | default false
year_rate       | INT           | no       | year covered when is_final_rate=true

UNIQUE
  uq_apg_weight_date  (apg, effective_date)

4. apg_base_rates
================================================================================
PURPOSE  Base rate (dollars per APG-weight unit) by source, peer group,
         region, and effective date. Drives every APG line payment.
SOURCE   PMTAC "Updated APG Fee Calculator" workbook ("Updated APG Base
         Rate" sheet) for source='dtc'. Hospital rates from legacy workbook.
SHAPE    Long form: one row per (source, peer_group, region, effective_date).

COLUMN              | TYPE          | NOT NULL | NOTES
--------------------|---------------|----------|----------------------------
id                  | INT (auto)    | yes      | PK
source              | VARCHAR(16)   | yes      | indexed; 'dtc' | 'hospital'
peer_group          | VARCHAR(64)   | yes      | indexed; e.g. 'Clinic*',
                                                | 'Amb Surg', 'Renal',
                                                | 'School-Based Health Center
                                                |  (SBHC)*', etc.
cure_code           | VARCHAR(32)   | no       |
base_rate_code      | VARCHAR(32)   | no       | NYS DOH rate code (e.g. '1407')
blend_rate_code     | VARCHAR(32)   | no       | (e.g. '1411')
capital_rate_code   | VARCHAR(32)   | no       | (e.g. '1409')
region              | VARCHAR(16)   | yes      | indexed; 'Upstate' | 'Downstate'
cheat_flag          | VARCHAR(32)   | no       | hospital-only metadata
effective_date      | DATE          | yes      | indexed
rate                | DECIMAL(12,4) | yes      | dollars

INDEXES
  ix_base_rate_lookup  (source, peer_group, region, effective_date)

LOOKUP RULE (engine):
  WHERE source         = :provider_type
    AND peer_group     = :peer_group       -- exact match, no fuzzing
    AND region         = :region
    AND effective_date <= :dos
  ORDER BY effective_date DESC
  LIMIT 1

================================================================================
PORTING NOTES
================================================================================

A. JSON columns (other_diagnoses, modifiers, line_details, raw_payload, details)
   - SQLite        : TEXT (we serialize/deserialize in app code)
   - SQL Server    : NVARCHAR(MAX) on 2014-, JSON column type 2016+
                     EF Core: HasConversion(...) or .HasJsonProperty(...)
                     EF6:     ValueConversion is not native; do it in the
                              entity getter/setter or via DbCommandInterceptor
   - PostgreSQL    : JSONB (preferred), with GIN index if you query into it

B. Boolean columns
   - SQLite        : INTEGER 0/1 transparently
   - SQL Server    : BIT (0/1). EF6 maps bool <-> bit cleanly.
   - PostgreSQL    : BOOLEAN

C. Default timestamps
   The Python service writes UTC datetimes via datetime.utcnow() in code.
   When porting:
   - EF Core / EF6 : set default in OnModelCreating with HasDefaultValueSql
                     ('GETUTCDATE()' for SQL Server)
   - Or keep app-level defaults to match Python behavior exactly.

D. Decimal precision (REPEAT — important)
   Money columns use DECIMAL(14,2). APG weights use DECIMAL(12,6).
   Base rates use DECIMAL(12,4). Compression percentage uses DECIMAL(10,4).
   These precisions are LOAD-BEARING. Do not widen to FLOAT/REAL/DOUBLE
   anywhere in the chain — money math must remain exact.

E. String column lengths
   These were chosen to match observed source data + reasonable headroom.
   Increasing them is harmless; shrinking risks truncation (especially
   eapg_desc and description which can be long-form clinical text).

F. Identifier/sequence semantics
   Python/SQLite   : INTEGER PRIMARY KEY autoincrement
   SQL Server      : INT IDENTITY(1,1)
   PostgreSQL      : SERIAL or BIGSERIAL
   Existing data exports do NOT include IDs; downstream re-inserts get
   fresh IDs. Don't try to preserve PKs across a port — relationships
   are by foreign keys, which the ORM remaps.

G. Cascade behavior
   parsed_claim -> children: ON DELETE CASCADE  (clearing a claim drops
                                                  all its lines/CAS/APG rows)
   user_account -> audit_log: ON DELETE SET NULL (audit rows survive a
                                                  user purge for compliance)
   linked_claim_id_fk:        ON DELETE SET NULL (un-linking, not cascade)
   Preserve these exactly when porting — they encode policy decisions.

H. Master Reset semantics (admin-only; see DELETE
   /api/admin/master-reset-reference-data)
   WIPES:    apg_base_rates, hcpcs_to_eapg, icd10_to_eapg, apg_weights,
             px_based_weights, fee_schedule, cms_rate_cache
   PRESERVES: user_account, audit_log, provider_config, provider_county,
              zip_locality, parsed_claim, parsed_service_line,
              claim_adjustment, apg_result
   Use /api/claims (DELETE) to clear claim history separately.
